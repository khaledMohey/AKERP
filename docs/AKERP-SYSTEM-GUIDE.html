1) رؤية المنتج ونموذج البيع

AKERP نظام تخطيط موارد مؤسسات (ERP) موجّه للسوق العربي، يُباع كمنتج قابل للتخصيص دون إعادة بناء النظام لكل عميل.

الموديولات المستهدفة في المنتج الكامل:

  • لوحة تحكم Dashboard
  • المخزون Inventories
  • المبيعات Sales
  • المشتريات Purchase
  • العملاء والموردين Partners
  • المناديب Sales Representatives
  • الحسابات Accounting
  • التقارير Reports
نموذج الإيرادات المزدوج (من نفس الكود):
  • إيجار / اشتراك (Subscription): العميل يدفع دوريًا، المالك يستطيع الإيقاف/التمديد/التحديث مركزيًا.
  • بيع نهائي (Perpetual): العميل يشتري ملكية، غالبًا تشغيل أوفلاين/محلي، بدون تاريخ انتهاء اشتراك.

يمكن تحويل عميل من إيجار إلى بيع لاحقًا بتغيير نوع الرخصة ونقل/ضبط مكان البيانات — بدون عمل نسخة كود جديدة.

2) مبادئ التصميم الحاكمة

  1. كود واحد: لا يوجد مشروع Sale منفصل ومشروع Rent منفصل.
  2. السلوك بالرخصة والإعدادات: الفرق يظهر عبر LicenseType و Features/Settings.
  3. التخصيص بالبيانات لا بالـ forks: كل عميل له company_id.
  4. واجهة ويب حديثة داخل ديسكتوب: Blazor/MudBlazor هو مصدر الواجهة، Desktop غلاف WebView2.
  5. Modular Monolith: لا Microservices في المرحلة الحالية.
  6. ابنِ الكل على مراحل: النطاق كامل، لكن التسليم مرتب.
ممنوع: شروط مثل if (clientName == "شركة س")، أو نسخ مجلد المشروع كاملًا لكل عميل، أو كسر السلوك الافتراضي عند تنفيذ طلب خاص.

6) ما تم إنجازه بالتفصيل

مرحلة 0 — تأسيس المشروع والواجهة

  • إنشاء الحل والمشاريع الستة.
  • واجهة MudBlazor عربية RTL بألوان Teal/Sky.
  • قوائم لكل الموديولات (حتى غير المنفذة) كهيكل تنقّل.
  • غلاف Desktop بـ WebView2.
  • توثيق أولي في README.

مرحلة 1 — أساس المنتج (منجز)

  • Login/Logout/Session: جلسة محفوظة في المتصفح عبر ProtectedSessionStorage.
  • حسابات العملاء (/companies): إنشاء عميل = شركة + رخصة + يوزر دخول + إعدادات افتراضية.
  • المستخدمين (/users): إدارة مستخدمي الشركة الحالية.
  • الرخص (/license): اختيار أي عميل، تحويل إيجار↔بيع مع أثر حقيقي في DB (تاريخ انتهاء أو null).
  • التخصيص (/features): Features + Settings حسب الشركة.
  • Seed: شركة تجريبية + admin/admin123.
  • LAN rental test: profile lan على منفذ 5088 + نشر DesktopClient مع server.json.
حساب تجريبي: المستخدم admin — كلمة المرور admin123

شاشات Placeholder فقط (بدون منطق أعمال بعد)

  • /inventory — المخزون
  • /sales — المبيعات
  • /purchase — المشتريات
  • /partners — عملاء وموردين
  • /reps — المناديب
  • /accounting — الحسابات
  • /reports — التقارير
  • أرقام الـ Dashboard ما زالت تجميلية (أصفار)

7) المراحل القادمة بالتفصيل

مرحلة 2 — التشغيل اليومي (الأولوية التالية)

  1. Partners: عميل/مورد/الاثنين، حد ائتمان، رصيد افتتاحي، كشف حساب أولي.
  2. Inventory: أصناف، وحدات، باركود، مخازن، وارد/منصرف/تحويل/تسوية، جرد، حد الطلب، تكلفة (متوسط مرجح أولًا).
  3. Sales: عرض سعر → أمر بيع → فاتورة → مرتجع → تحصيل؛ خصم/ضريبة.
  4. Purchase: طلب → أمر → استلام → فاتورة مشتريات → مرتجع.
  5. كل المستندات تُقيّد بـ CompanyId وتؤثر على المخزون حيث يلزم.

مرحلة 3 — الميدان والمالية

  1. المناديب: مناطق، ربط عملاء، أهداف، عمولات (flat/tiers عبر settings)، تحصيلات.
  2. الحسابات: دليل حسابات، قيود يدوية + آلية من الفواتير، صناديق/بنوك، ذمم.
  3. تقارير أساسية + PDF.
  4. Dashboard بأرقام حقيقية.

مرحلة 4 — المنتج التجاري

  1. تفعيل AKERP.Api للتحكم السحابي بالاشتراكات.
  2. Admin Panel للمالك: تفعيل/إيقاف/باقات.
  3. Auto-update للديسكتوب.
  4. ملف رخصة موقّع لعملاء البيع النهائي الأوفلاين.
  5. تعدد المستخدمين كمنتج (LAN/Cloud).

مرحلة 5 — Hybrid Offline للإيجار

  1. عمل أوفلاين مع مزامنة.
  2. Grace period عند انقطاع النت.
  3. معالجة التعارضات.

مرحلة 6 — تخصيص متقدم

  1. Custom Fields.
  2. قوالب طباعة لكل شركة.
  3. Behavior variants أوسع.
  4. Plugins فقط للطلبات الكبيرة غير القابلة للإعدادات.

10) تشغيل محلي وتجربة LAN

تطوير عادي

dotnet run --project src/AKERP.Web --launch-profile https
# https://localhost:7114

تجربة إيجار بين لابين على نفس الشبكة

  1. على جهاز السيرفر: اعرف IP عبر ipconfig.
  2. اسمح بالمنفذ 5088 في Firewall (Admin): 
    netsh advfirewall firewall add rule name="AKERP LAN 5088" dir=in action=allow protocol=TCP localport=5088
  3. شغّل: 
    dotnet run --project src/AKERP.Web --launch-profile lan
  4. انشر الديسكتوب: 
    powershell -ExecutionPolicy Bypass -File deploy/lan/publish-desktop.ps1 -ServerIp "IP_HERE"
  5. انسخ deploy/lan/DesktopClient للاب الثاني، وتأكد من server.json.
  6. أنشئ عميل إيجار من /companies وادخل بيوزره على اللاب الثاني.

11) دليل المساهم / Cursor Agent

قبل أي تعديل جوهري: اقرأ AGENTS.md وهذا الـ PDF. لا تبدأ مرحلة 4–6 قبل إكمال أساس مرحلة 2 إلا لسبب واضح متفق عليه.
  1. افهم أن المهمة القادمة الطبيعية هي مرحلة 2.
  2. أي كيان تشغيلي جديد يجب أن يحتوي CompanyId.
  3. أي اختلاف بين العملاء = Feature/Setting/Variant.
  4. حافظ على RTL وثيم MudBlazor الحالي.
  5. لا تكسر شاشات الإدارة الحالية (Companies/Users/License/Features).
  6. بعد إنجاز جزء كبير: حدّث قسم المراحل في AGENTS.md.
  7. لا ترتكب أسرار أو قواعد بيانات إنتاج في Git.
  8. التزم بـ .NET 8 و EF Core الحاليين.

أولوية مقترحة للمساهم الجديد:

  1. Partners module
  2. Inventory module
  3. Sales module
  4. Purchase module
